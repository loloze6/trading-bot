## Top findings (most severe first)

1. **Card D's asset variant cannot exist (D.2, E.1, E.2).** Evidence: `STRATEGY_DESIGN_GUIDE.md:396-417`, `rpr:1431-1437`, `run_protocol.py:1968`, `innovation-expansion/SKILL.md:251-256`. Consequence: every variant runs the same coins, so "the result does not depend on the coin" is never tested, and the "asset" variant is really a second design variant.
2. **Crashed variants silently drop out of the grid (C.2).** Evidence: `rpr:1524-1572, 1679-1686`; `campaign_memory.py:430-433`; `test_e033_slice4a_variant_loop.py:395-446`. Consequence: an engineering failure can produce a `validated` block judged on two or even one variant, and that block then feeds composition and the profit-bars stop.
3. **One symbol per variant is not honoured (C.6).** Evidence: `run_protocol.py:1968`; `vce:1504-1513`; menu `symbol_reducer: null` with no override allowed. Consequence: criteria pool BTC and ETH together, so a coin that fails can be masked by a coin that passes.
4. **The cost criterion passes ideas that lose money (E.3).** Evidence: `criterion_menu.yaml:35-38` (`> 0.3`, unratified). Consequence: an idea whose gross edge covers only 30% of fees clears the only cost criterion, where the card intended "survives 2× costs".
5. **Scale-free refusal is not implemented, and operator briefs bypass the menu (B.1, B.3).** Evidence: `scale_free` is not read in any `.py`; `run_campaign.py:438-449, 476-485`; `rpr:5679-5683`. Consequence: an operator-brief run is graded on whatever pass_rule the brief carries, possibly non-scale-free or floorless, and 1a's criteria for it are ignored.
6. **Half of the criterion menu is missing (B.2).** Evidence: `criterion_menu.yaml:23-105`. Consequence: most forecast ideas can only be judged on net-return sign consistency and edge/cost. There is no IC, correlation or regime-conditional criterion, so "idea criteria are usually not about profit" does not hold in practice.
7. **The FAIL-dominates tie-break is labelled OPERATOR-CONFIRMED but was never confirmed (C.5).** Evidence: `vce:1640-1641` against `E-046b/S1_FINDINGS.md:365-369` and `SESSION_LOG.md:40,47`. Consequence: an idea with one FAIL and one under-floor cell is recorded as refuted rather than inconclusive, on an autonomous call still awaiting Jeremy.
8. **Composite assembly moved from the 1b LLM to code without a recorded decision, and composites use the pinned run's coins rather than the campaign target set (F.4, F.7, B.6).** Evidence: `rpr:3886-3911`; `composition.py:1-60`; `decide_next.py:1191-1262`; `target_instrument_set` read only at `rpr:2392,2439`. Consequence: the regime/sub-strategy design step of card F never happens, and the profit-bars stop can fire on a coin set the campaign did not declare.
9. **The variant-count rule is loose (D.1).** Evidence: `rpr:12291-12355, 12318-12319, 11655, 11673-11675`; no cap in code. Consequence: with the data gate off, or with repeats, an idea runs on fewer than three variants, and nothing stops more than four variants inflating the trial count.
10. **Unratified placeholders are live once the flags flip (A.5, B.5).** Evidence: `profitability_bars.yaml:120-129` (`ratified_by: null`); `criterion_menu.yaml:129-138` (`ratified: false`); no code gate. Consequence: flipping the flags makes the stop and residual-IC validation run on invented thresholds, and nothing warns at run time.

## Could not verify
- **Real-model behaviour:** whether a real 1b/innovation-expansion LLM writes a meaningful "asset patch", or ever emits a `regime`-kind manifest. No run on disk has used `config_direct_authoring` or the readers. `untestable_without_run`.
- **What card G means by "attempt":** a queue attempt, or a DSR trial. The code counts an inconclusive idea's successful backtests in DSR, which is right for data-spend accounting. The operator should state which meaning was intended.
- **The equal-weight portfolio decision (2026-09-24):** found only as a yaml comment and a register note, not as an S1 Decision section. I could not confirm whether it was meant to cover Sharpe and the trade floor as well.
- **`trade_count_min` semantics:** "minimum per-coin `min_trade_count`" may be a per-window minimum, which could be much stricter than intended. Not traced into `promotion` or `run_protocol`.
- **Composite-cache, R1 and composition end to end on real data:** blocked by the empty registry. `untestable_without_run` (E-060 S4 budget).
- **Pooled floors with `min_n_eff` on operator criteria:** would raise NotImplementedError and turn a run into a grid SPEC_ERROR, then a failed run under retired routing (`rpr:4267-4269`). Inferred from the code; not executed.
