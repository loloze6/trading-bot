Fidelity:
- Situation: a coin's 30-day return relative to its daily volatility over the past 60 days -> kept: the 30-bar return divided by the standard deviation of the last 60 daily returns.
- Comparison: its normal drift -> kept: the forward return minus the coin's mean 10-day return over all windows.
- Outcome: the larger that ratio, the more the coin rises over the next 10 days -> kept: a 10-bar hold, with a long sized by the ratio's strength and flat when the ratio is not positive.
- Verdict transfer: yes: the forecast is the idea's own ratio, held for the idea's 10 days and judged against the coin's drift.
Forecast: The forecast uses one indicator, VolatilityScaledReturnComponent (period 30, vol_period 60). This is the 30-day return divided by (the 60-day standard deviation of daily returns × √30). It is standardised against its own past 60 values, so a typical size is 10, capped at 20. It is then clipped at 0, so the forecast is long-only. It is positive, and grows with the size of the volatility-adjusted month-long rise, when the coin rose over the 30 days. It is 0 when the coin did not rise. There is no regime, because the idea is a steady graded relation and not a condition.

Criterion:
- Horizon: 10 bars
- Main measure: The cases are the bars on a non-overlapping 10-bar grid in each window. For each case, take the coin's 10-bar forward return minus its mean 10-bar return over all windows. Regress this excess return on the forecast (post_pipeline_value) at that bar, pooling cases of the same day. The measure is the slope and its t, before costs.
- Supporting check: none
- Confirm: The slope is positive with t ≥ 2: the excess 10-day return grows with the size of the volatility-adjusted rise.
- Reject: The slope is negative with t ≤ -2: larger volatility-adjusted rises are followed by smaller-than-drift returns.
- Inconclusive: Any slope with |t| < 2 is inconclusive. So is a test with fewer than 200 grid cases with forecast > 0, or fewer than 1000 grid cases in total.
