Fidelity:
- Situation: an up day that ends a run of down days, while the 20-day return is deeply negative -> adapted: the up day and the deep slide (the 20-day return at or below -1 usual 20-day move) become regime conditions. Inside them the forecast is graded by the slide's depth and by the run's down days beyond the first. The depth can be graded. The run length cannot: standardised, it is only 0 or the cap.
- Comparison: deeper 20-day decline against the coin's own swing, and more down days beyond the first -> replaced: the run part becomes a step (0 for a one-day run, the +/-20 cap for two days or more).
- Outcome: a fall over the next day -> kept
- Verdict transfer: no: the run's length no longer grades the position, so the idea's "the more down days, the larger the fall" is not tested.
Reason: `PriorDownRunOnUpCloseComponent` (`form` "beyond_first") is an integer that is nonzero on about one bar in eight. `standardise` divides it by its mean absolute value over all past bars, about 0.25. So a run of two down days already gives the cap of 20, and the run length becomes on/off. No other component reads the length of the down run that today's up close ends, and no catalogue composition gives a product that grades it continuously together with the slide's depth.
