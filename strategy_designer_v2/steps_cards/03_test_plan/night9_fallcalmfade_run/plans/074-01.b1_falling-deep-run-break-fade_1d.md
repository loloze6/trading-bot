Fidelity:
- Situation: the first up day after a run of consecutive down days, in a falling market -> kept: a regime rule on `PriorDownRunOnUpCloseComponent` (run of 2 or more down days, the usual meaning of "a run"); the profile is added by code.
- Comparison: the run's return over its down days, against the usual daily swing over the last 30 days -> kept only with a missing component: no catalogue component, alone or combined, gives this ratio on the up day.
- Outcome: the close falls over the next day, more after deeper runs -> kept: short, horizon 1 bar on daily bars.
- Verdict transfer: no: without the run-depth measure the forecast cannot be graded by the idea's strength, so no plan can be built.
Reason: `DownStreakLossInUsualMovesComponent` measures a down run's loss in usual moves only while the run lasts, and is 0 on the up day that ends it. No component reads the finished run's loss on that up day. Fixed-period lagged returns (`VolatilityScaledReturnComponent`, `lag` 1) cannot follow a run whose length varies, and they divide by the square root of the period. One regime per run length does not fit either: there are only three usable regimes and the profile vetoes, and runs can be longer.
