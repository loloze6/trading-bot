## Inspector notes

### (1) Design and mechanism

1. The brief's machine content is six required keys plus `machine_constraints`; the rest reaches the pipeline only as text in the 1a and 1b prompts. Verified: `_materialize_run` copies every key but `machine_constraints` into `research_brief.yaml` (`RC:786`), and the 1a handoff names that whole file as primary input (`handoffs/research_brief_to_hypothesis.yaml:5-8`). `scope` has no code reader (grep over `workflow/` and `tools/`: the `scope` hits are the profit-bars and claim-findings keys, not the brief's); `available_data` has no reader at all, not even in a skill text (grep over `workflow/`, `tools/`, `workflow_artifacts/skills/`: no hit). So `available_data` is a field the operator fills for nobody. Lead for note 2.1.
2. `criteria_from: hypothesis_generation` is load-bearing, not a decorative default (the operator asked why it is not simply empty). An operator brief with neither `criteria_from` nor `evaluation` materialises with `pass_rule: null` (`RC:819`), `_write_pass_rule_from_card` returns `False` for it (`RP:8399-8400`: no `candidate`, no brief-level marker, `RP:8175-8184`), so 1a's criteria are never written into `pre_registration.yaml`; downstream the rule is "not menu-shaped" and no grid is written (`RP:5930-5933`; the evaluator's `legacy_not_evaluable` path, `verdict_criteria_evaluator.py:914-928`). The run would then spend its backtests and end without a branch-1 verdict. A missing line silently degrades the run instead of refusing it; the template comment `:43` ("Left as it is, step 1a picks") does not say that deleting it is not the same as leaving it. For autonomy: a decide-next brief always carries the marker or the fold child's criteria (`decide_next.py:2808-2811`), so the loop itself is safe; only hand-written briefs can fall into this.
3. `constraints` (exact config) without a claim: 1a still runs first and writes the card and claim from `research_goal`; 1b is then replaced by code (`_exact_config_1b`, `RP:17089-17134`, flag `exact_config_1b` on at `campaign_config.yaml:1008-1009`). Nothing at this stop ties the exact config to the claim 1a wrote; whether `_claim_gate_before_1b` (`RP:17865`) checks that is stop 10's question. The operator's reading is right as far as this stop shows: an exact config is built regardless of what 1a concluded.
4. For a fold brief, `start`, `end` and `window_months` are required by code but unused for the windows: `_ensure_protocol_from_constraints` reads `proto_constraint["start"]` and `["end"]` unconditionally (`RP:10681-10682`, a KeyError if absent) and passes them to `_protocol_windows_from_constraints`, whose fold branch ignores them (`RP:10626-10637`). Decide-next derives them from the fold (`fold_protocol`, `decide_next.py:2614-2623`, `fold_span` `research_folds.py:234-237`); the operator brief of run_101 carries fold A's span by hand (`sma_trend_1h_fold_a.md:76-78`, years 2022-2023, equal to `folds.yaml:40-45` first start / last end). So the operator's "why both" has a code answer: the keys are mandatory inputs that the fold then overrides. Deriving them from the fold would remove a hand-copy and one way to be wrong.
5. The duplication of `market_universe`/`symbols` and `timeframe`/`protocol.timeframe` is enforced, not tolerated: `_lint_brief_protocol_agreement` refuses a mismatch at registration (`RC:515-544`), and `machine_constraints.protocol` carries no `venue` (`RC:483-484`), the protocol's venue coming from the brief's `venue`/`product` at generation. Two of the three protocol identity keys are therefore copies of brief keys that a lint keeps equal; one source would do.
6. A decide-next brief carries no `scope` block (`decide_next.py:2664-2665` copies five keys only), while the 1a skill says the brief arrives "with its scope block" and that every `idea_quantities` formula "must be computable from the feeds in the brief's scope block" (`hypothesis-design/SKILL.md:10,31`). Every child run's 1a therefore runs without the text the skill tells it to use. On the live loop (run_102 was itself a child, `run_102/artifacts/research_brief.yaml` has no `scope`), this is the common case, not the exception.

The scope block, when present, is 8 lines of prose carrying about 25 `file:line` pointers (`template :59-64`), several already stale: it cites `claim_tests.py:579-581`, `:631-632`, `:682-683`, `:748-749`, `:881` for the selector/outcome/baseline/statistic lists and `check_spec`; on this checkout those are `SELECTORS :719`, `OUTCOMES :778`, `BASELINES :838`, `STATISTICS :904`, `check_spec :1110`.
